# 1. Приём и модель данных

## Границы ответственности

Submission и AIDeclaration представлены frozen dataclass. Парсер получает данные и возвращает Submission либо SubmissionError(code, field, message). Он не читает stdin, не выполняет сетевые запросы и не изменяет вход. CLI отвечает за аргументы и файлы; репозиторий отвечает за хранение; сервис отвечает за duplicate/conflict.



## Проверки входа

Отклоняются повторяющиеся JSON-ключи, NaN и бесконечности, повреждённый JSON, неизвестные и отсутствующие поля. Требуется schema_version=1 с точным типом int, исключающим bool. Идентификаторы непусты; timestamp включает зону; text или code содержит непустой текст. В декларации поля used и verified_by_student имеют тип bool; при used=true требуются непустые tool и purpose. Аннотации описывают контракт, но не выполняют эти проверки.



## Устойчивое представление

Все поля Submission преобразуются через asdict в канонический JSON: ключи сортируются, разделители компактны, Unicode сохраняется, NaN запрещён. UTF-8 байты передаются SHA-256; результат имеет 64 шестнадцатеричных символа. Пробелы внутри текста и кода не удаляются. Строка timestamp сохраняется: эквивалентные моменты в разных строковых формах могут иметь разные хеши. Встроенный hash() не используется как устойчивый идентификатор содержимого.



## Приём повторов

Новый submission_id сохраняется. Повтор того же ID с тем же хешем возвращает ранее сохранённый объект. При отличающемся содержимом возникает conflict без замены. Новая версия использует новый ID. Хранилище in-memory прекращает существовать после завершения процесса; операция get/add не является конкурентной транзакцией.



# 2. Анализаторы и контракты

## Интерфейс и композиция

Analyzer(Protocol) задаёт синхронный метод analyze(submission, context) → AnalysisReport. Явное наследование от Protocol не требуется: существенны доступные операции и их типы. В отличие от этого, наследование SubmissionError от Exception определяет семейство исключений. Контекст содержит Assignment и снимок дополнительных работ. Протокол источника определяет open(); реализации выдают строки через контекстный менеджер.



## Три реализации

LengthAnalyzer считает непустые строки text/code, включая комментарии, выдаёт rubric_feedback и score=null. TemplateAnalyzer ищет полный точный непрерывный блок разрешённого шаблона, сохраняет отступы и поясняет разрешённое совпадение; это не доказательство плагиата или оригинальности. AIDeclarationAnalyzer описывает декларацию, проверяет обязательные сведения при used=true и требует просмотр при неподтверждённой проверке студентом. Декларация не является доказательством авторства или правильности.



## Расширяемость

Реестр сопоставляет имя с фабрикой. Центральный сервис создаёт выбранный объект и вызывает общую операцию analyze; ветвления по конкретным классам нет. Третий анализатор подключён новой записью реестра, без изменения алгоритма выбора. Новый экземпляр создаётся для каждого вызова.



## Результаты и защита

Отчёт содержит ID и хеш работы, ID и версию анализатора, config_hash, observations/findings, время с зоной и review_required. Evidence ссылается на исходные строки с нумерацией от 1; границы включены. Сервис передаёт копии входа, выявляет сохраняющиеся изменения и проверяет метаданные и границы отчёта. Неожиданное исключение компонента преобразуется в analyzer_error; некорректный отчёт отклоняется. Это защита от ошибок компонента, а не песочница для вредоносного кода.



# 3. Источники, проверки и измерения

## Жизненный цикл ресурса

InMemoryLineSource сохраняет строки в tuple и при открытии создаёт новый итератор. JsonlFileSource открывает UTF-8 файл и закрывает его при выходе из with. Общий контракт проверяет порядок, Unicode и повторное открытие. Отдельно проверены закрытие после чтения одной строки и закрытие при исключении. Сам по себе break не гарантирует закрытие произвольного итератора; ресурс освобождается при выходе из управляющего with.



## Покрытые сценарии

Исчерпывающее доказательство корректности этим не утверждается.

## Ограничения

Нет постоянной БД, HTTP API, многопоточности, автоматической оценки решений или детектора ИИ. Источник памяти материализует строки. Контекст дополнительных работ пока не заполняется CLI. При ошибке записи файл отчётов может быть частичным. Дубликат в одном запуске не анализируется повторно, даже если предыдущая попытка анализа дала ошибку. Повторный запуск требует нового имени выходного файла. Конфигурация измеряется и идентифицируется, но полная система аудита изменений не реализована.
